Handbuch – Signier-Werkzeug {{VERSION}}

Das Werkzeug signiert Programmversionen mit einem eigenen Schlüssel (Ed25519), damit die eingesetzte Software nur Versionen annimmt, die wirklich vom Herausgeber stammen. Der private Schlüssel verlässt diesen Rechner nie; er liegt mit Kennwort verschlüsselt im Datenordner.

1. Profile & Schlüssel

  • Je Software ein Profil: „Speedrace-Dashboard“ (feste Regeln des Dashboards) oder „andere Software“ (alle Dateien außer Ausnahmen).
  • „Neuen Schlüssel erzeugen“ (Kennwort mind. 12 Zeichen) oder eine vorhandene .pem übernehmen. Den Ordner schluessel im Datenordner zusätzlich auf einen USB-Stick sichern.
  • Den öffentlichen Schlüssel dort eintragen, wo geprüft wird. Für „andere Software“ erzeugt „Prompt erzeugen“ einen Text, mit dem eine andere Sitzung die Prüfung einbaut.

2. GitHub

  • Ein Token (fein granular, Rechte „Contents: Read and write“ für das Repository) eintragen. Es wird unter Windows mit DPAPI verschlüsselt gespeichert.

3. Signieren

  • Vorher: VERSION (Form x.y.z) erhöhen, committen und pushen.
  • „Von GitHub laden, signieren und hochladen“: lädt den Stand des Zweigs, signiert, lädt SIGNATUR.json (beim Dashboard auch SIGNATUR-BAU.json) in einem Commit hoch und setzt den Tag v<Version>. Erst danach verteilen.
  • Gibt es den Tag schon, bricht das Werkzeug ab, bevor etwas hochgeladen wird – Tags werden nie verschoben.
  • „Paketliste prüfen / signieren“ (nur Dashboard): signiert die getestete PAKETE.lock vom Zweig „pakete“ (Python-Pakete und, falls angegeben, die cloudflared-Version).
  • „Ordner signieren“: für einen Ordner auf diesem Rechner (alle Dateien darin, auch nicht eingecheckte).

4. Prüfen

  • Prüft einen GitHub-Stand oder Ordner gegen die Signatur: zusätzliche, fehlende und veränderte Dateien werden aufgelistet.

5. QNAP

  • Führt Schritt für Schritt durch Installieren, Neubauen, Zurück zur vorigen Version und Aufräumen auf dem NAS. Jeder Befehl wird vorher angezeigt und erst nach Bestätigung in einem Konsolenfenster ausgeführt; das Ergebnis meldest du zurück.
  • Vor jedem Neubau werden die Bau-Dateien geprüft (Ergebnis 0: frei, 1: nur nach Bestätigung, 2: gesperrt). Ein beiseitegelegter alter Ordner bleibt der Rückweg, bis „Aufräumen“ ihn löscht.

6. Updates des Werkzeugs

  • Neue Versionen erscheinen oben als „Update“. Sie werden nur eingespielt, wenn die Signatur des Herausgebers gültig ist.

Daten

Profile, Schlüssel, Protokolle: %APPDATA%\Signier-Werkzeug. Ausführlich: README.md und SICHERHEIT.md im Repository {{REPO}}.
